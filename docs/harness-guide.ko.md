# 하네스 가이드 (한국어)

> EduHarness Foundation 상세 사용 가이드

---

## 1. 하네스 엔지니어링이란?

### 비유: 말과 안장

AI 모델은 말(馬)입니다. 강력하지만 방향이 없습니다.
하네스는 안장이고 고삐입니다.

- **같은 말(모델)**이라도 안장과 고삐가 다르면 전혀 다른 결과가 나옵니다
- 하네스를 깎는 사람은 기수도 말도 아닌, 안장을 만드는 사람입니다
- 개발의 본질이 변했습니다: 코드를 "쓰는 일"에서 AI가 달릴 "궤도를 설계하는 일"로

### 원문 4대 구성 요소와 기술 4대 기둥 매핑

하네스 엔지니어링 원문은 4가지 구성 요소를 정의합니다. EduHarness는 이를 기술적으로 구현합니다:

| 원문 구성 요소 | 역할 | 기술 관점 | EduHarness 파일 |
|---|---|---|---|
| 📜 **헌법** | AI가 따를 규칙과 원칙 | Context + Constraint | `CLAUDE.md`, `AGENTS.md` |
| 🏗 **작업 구조** | 무엇을 어떻게 만들지 | Context | `architecture.md`, `progress.md` |
| ✅ **검증** | 결과물 품질 판단 기준 | Verification | `.husky/pre-commit`, 체크리스트 |
| 🔄 **실행 루프** | 수정→검증→반복 워크플로우 | Feedback + Loop | `.claude/skills/execution-loop/` |

## 2. 각 파일 상세 설명

### CLAUDE.md — AI 핵심 규칙서

AI 에이전트가 세션을 시작할 때 자동으로 로드합니다.
**가장 먼저 수정해야 할 파일**입니다.

**포함해야 할 내용**:
- 프로젝트 목적 (AI가 "무엇을 위한 코드인지" 알게)
- 코딩 규칙 (TypeScript, 불변성, 파일 크기 등)
- 금지 행동 목록 (파일 삭제, 스키마 변경 등)
- 완료 기준 (테스트 없이 완료 선언 금지)
- 주요 명령어 (개발 서버, 테스트, 빌드)

**주의**: 너무 길면 AI가 모두 읽지 않습니다. **핵심만 간결하게** 유지하세요.

### AGENTS.md — 에이전트 역할 분리

AI의 인지 부하를 줄이기 위해 역할을 4가지로 나눕니다.

```
Planner → Coder → Reviewer → Coder (수정) → Tester
```

**언제 역할 분리가 효과적인가?**
- 복잡한 기능 구현 시 (3개 이상 파일 영향)
- 코드 리뷰가 필요할 때
- 테스트 강화가 필요할 때

단순 수정 (1~2줄)은 역할 없이 진행해도 됩니다.

### architecture.md — 시스템 구조 가이드

AI가 코드를 작성하기 전에 읽는 "설계도"입니다.

**핵심**: AI에게 "이 파일이 어디에 있어야 하는지", "이 함수가 어떤 다른 모듈을 사용하는지"를 알려줍니다.

**업데이트 시기**:
- 새로운 주요 컴포넌트 추가 시
- 데이터 모델 변경 시
- 디렉토리 구조 변경 시

### progress.md — 진행 상태 추적

AI와 사람 모두를 위한 "현재 위치 표시판"입니다.

**AI 에이전트에게 주는 이점**:
- 새 세션에서도 이전 작업 맥락 파악 가능
- 중복 작업 방지
- 다음 할 일 우선순위 명확

**업데이트 규칙**: 작업 시작 전 읽고, 완료 후 반드시 업데이트

## 3. 스킬 활용법

스킬은 AI 에이전트에게 "전문 역할"을 부여합니다.

### edu-component 스킬

```
[edu-component 스킬 사용] 학생 성적 표시 카드를 만들어줘.
이름, 점수, 순위를 보여주고 WCAG 2.1 AA 접근성을 갖춰야 해.
```

AI가 이 스킬을 로드하면:
- 교육용 컴포넌트의 접근성 기준을 자동 적용
- ARIA 속성 자동 포함
- 테스트 코드 함께 생성

### accessibility 스킬

```
[accessibility 스킬 사용] src/pages/quiz.tsx를 검토해줘.
접근성 이슈를 CRITICAL/HIGH/MEDIUM으로 분류해줘.
```

### progress-update 스킬

작업 완료 후 자동 또는 수동으로:
```
[progress-update 스킬 사용] 로그인 기능 구현 완료.
JWT 토큰 방식 선택, 리프레시 토큰 포함.
```

## 4. pre-commit 훅 설정

`.husky/pre-commit` 파일은 커밋 전에 자동으로 실행됩니다.

### 기본 설정 활성화

```bash
# 1. Husky 설치
npm install --save-dev husky

# 2. Husky 초기화
npx husky init

# 3. pre-commit 훅 파일을 EduHarness 버전으로 교체
cp .husky/pre-commit .husky/pre-commit.bak
# 이 리포지토리의 .husky/pre-commit 내용을 복사
```

### 커스터마이징

자신의 프로젝트에 맞게 수정하세요:

```bash
# .husky/pre-commit 예시

# ESLint가 없으면 이 블록 삭제
if [ -f "package.json" ] && grep -q '"lint"' package.json; then
  npm run lint
fi

# TypeScript가 없으면 이 블록 삭제
if [ -f "tsconfig.json" ]; then
  npx tsc --noEmit
fi
```

## 5. 하네스 강도 조절

### 너무 엄격하면?

증상: AI가 모든 작업에 승인을 요청하거나 매우 느림

해결:
- CLAUDE.md의 "금지 행동" 목록 줄이기
- "3개 파일 이상이면 승인" → "5개 파일 이상이면 승인"으로 조정
- 단순 작업용 빠른 프롬프트 따로 준비

### 너무 느슨하면?

증상: AI가 규칙을 무시하거나 progress.md 업데이트를 빠뜨림

해결:
- CLAUDE.md 상단에 "이것은 필수 규칙"이라고 명시
- 세션 시작 프롬프트에 규칙 준수 명시
- pre-commit 훅 강화

## 7. 하네스의 2계층 구조

하네스는 두 개의 분리된 계층으로 구성됩니다. 원문의 표현을 빌리면:

### 레포지토리 하네스 (Repository Harness)

> "회사 취업 규칙" — 어떤 교육 프로젝트에도 공통으로 적용

`.claude/` 폴더 전체가 여기에 해당합니다:
- `.claude/skills/` — 교육 도메인 공통 스킬 (평가 설계, 학습 흐름, 실행 루프)
- `.claude/settings.json` — 자동화 훅
- `.husky/pre-commit` — 자동 품질 검사

**clone 직후 이 계층은 건드리지 마세요.** 교육 도메인 규칙이 이미 내장되어 있습니다.

### 애플리케이션 하네스 (Application Harness)

> "팀 업무 매뉴얼" — 이 프로젝트 전용 규칙

루트 레벨 4개 파일이 여기에 해당합니다:
- `CLAUDE.md` — 헌법 (이 프로젝트의 목적·규칙)
- `architecture.md` — 작업 구조 (기술 스택·설계도)
- `AGENTS.md` — 역할 분리
- `progress.md` — 현재 상태

**`[대괄호]` 채우기 = 애플리케이션 하네스 구축**이 시작입니다.

## 8. 위임형 상사 모델

하네스를 잘 구축했다면, AI 지시 방식도 달라져야 합니다.
원문이 정의한 3가지 상사 유형:

### 지시형 상사 ❌ (피하세요)

모든 방법을 일일이 설명 → AI의 창의적 해결 공간 제한

```
"로그인 버튼은 #3B82F6으로, 텍스트는 white, 패딩은 12px 24px,
 border-radius는 8px로, hover 시 #2563EB로 변경해줘."
```

### 방임형 상사 ❌ (피하세요)

맥락 없이 결과만 요구 → 기대치에 미달하는 결과

```
"로그인 페이지 만들어줘."
```

### 위임형 상사 ✅ (하네스 철학)

목표와 기준을 제시하고, 방법은 AI에게 위임

```
"[Coder] 학생 로그인 페이지를 만들어줘.

 목표: 초등학생도 쉽게 쓸 수 있는 단순한 UI
 기준:
   - WCAG 2.1 AA 접근성 준수 (.claude/skills/accessibility/ 참조)
   - 만 14세 미만 생년월일 수집 (CLAUDE.md 규칙 5 참조)
   - 에러 메시지는 성장 중심 표현 (docs/education-principles.md 참조)
 완료 후: progress.md 업데이트"
```

### 위임이 잘 되는 3가지 조건

1. **측정 가능한 완료 기준** — "좋게" ❌ → "WCAG 2.1 AA 통과" ✅
2. **참조 문서 명시** — AI가 어디서 규칙을 찾아야 하는지 알게
3. **후속 행동 포함** — progress.md 업데이트처럼 마무리까지 지정

## 9. 자주 묻는 질문

**Q: CLAUDE.md가 너무 길어지면?**
A: docs/ 폴더로 분리하세요. CLAUDE.md는 "목차 + 핵심 규칙"만, 상세 내용은 docs/에 두고 참조 링크를 남기세요.

**Q: 새 세션마다 하네스를 다시 설명해야 하나요?**
A: 아니요. CLAUDE.md는 Claude Code가 자동으로 로드합니다. 세션 시작 시 "progress.md를 읽어줘"만 요청하면 됩니다.

**Q: 여러 개발자가 함께 사용할 수 있나요?**
A: 네. progress.md를 공유 상태 문서로 사용하고, 작업 전 `git pull`로 최신 상태를 가져오세요.

**Q: AI가 하네스 규칙을 무시하면?**
A: 1) 세션을 새로 시작하고 2) "CLAUDE.md를 다시 읽어줘"로 재로드 요청 3) 그래도 무시하면 CLAUDE.md 상단에 굵은 글씨로 핵심 규칙 강조
