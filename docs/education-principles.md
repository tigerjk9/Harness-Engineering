> Pedagogy Reviewer 역할이 이 문서를 기준으로 검토합니다.

## 1. 형성평가 vs 총괄평가

교육에서 가장 중요하고, 코드에서 가장 자주 혼동되는 개념.

### 형성평가 (Formative Assessment)

**목적**: 학습이 일어나는 **과정**에서 이해도를 확인하고 즉각 피드백 제공

특징:
- 점수보다 **피드백**이 핵심
- 틀려도 괜찮음 — 틀린 것을 통해 배우는 것이 목적
- 재시도는 권리, 제한은 교육적 해악
- 교사에게는 "어떤 개념을 더 가르쳐야 하나" 신호

실제 예시: 수업 중 퀴즈, 연습 문제, 체크인 질문, 화이트보드 활동

**코드에서의 의미**:
```
재시도 = 무제한
피드백 = 즉각, 설명 포함
정답 공개 = 즉시 또는 재시도 후
성적부 = 미반영 또는 낮은 가중치
심리적 압박 = 최소화
```

### 총괄평가 (Summative Assessment)

**목적**: 학습 **결과**를 측정하고 성취도 공인

특징:
- 점수와 성적이 핵심
- 공정성이 최우선 — 모든 학생에게 동일한 조건
- 재시도 불가 (일반적으로)
- 평가 무결성이 생명

실제 예시: 기말고사, 단원 평가, 수행 평가

**코드에서의 의미**:
```
재시도 = 불가 (maxAttempts: 1)
피드백 = 제출 후 일괄 또는 교사 설정
정답 공개 = 교사 설정에 따름
성적부 = 정식 반영
평가 무결성 = 최고 수준
```

### 왜 AI가 이를 혼동하는가?

AI는 "퀴즈" 기능을 요청받으면 일반적인 채점 시스템을 기본으로 구현합니다. 그 결과:

- 형성평가에 재시도 금지 로직을 적용 → 학생의 학습 기회 박탈
- 총괄평가에 즉각 정답 공개 → 평가 무결성 파괴

반드시 `CLAUDE.md`의 교육 도메인 규칙을 먼저 읽고 구현하도록 지시해야 합니다.

## 2. Bloom's Taxonomy (블룸의 분류 체계)

교육 목표를 6단계로 분류하는 체계. 1956년 발표, 2001년 개정.

```
      △ CREATE (창조)
     △△ EVALUATE (평가)
    △△△ ANALYZE (분석)
   △△△△ APPLY (적용)
  △△△△△ UNDERSTAND (이해)
 △△△△△△ REMEMBER (기억)
```

### 각 수준의 의미와 문항 유형

| 수준 | 한국어 | 대표 동사 | 문항 예시 |
|------|--------|-----------|-----------|
| REMEMBER | 기억 | 나열하다, 암기하다, 정의하다 | "광합성의 정의는?" |
| UNDERSTAND | 이해 | 설명하다, 요약하다, 분류하다 | "광합성을 쉽게 설명하면?" |
| APPLY | 적용 | 계산하다, 사용하다, 해결하다 | "이 공식으로 문제를 풀어라" |
| ANALYZE | 분석 | 비교하다, 분해하다, 원인을 찾다 | "두 방법의 차이는?" |
| EVALUATE | 평가 | 판단하다, 비판하다, 정당화하다 | "이 해결책이 최선인 이유는?" |
| CREATE | 창조 | 설계하다, 만들다, 제안하다 | "새로운 실험을 설계해보아라" |

### 코드 설계에서의 활용

```typescript
// LearningObjective에 Bloom 수준 연결
const lesson = {
  title: "분수의 덧셈",
  objectives: [
    { bloomLevel: "REMEMBER", text: "분자·분모를 정의할 수 있다" },
    { bloomLevel: "UNDERSTAND", text: "동분모 덧셈 원리를 설명할 수 있다" },
    { bloomLevel: "APPLY", text: "동분모 덧셈 문제를 풀 수 있다" }
  ]
}

// 평가 문항의 Bloom 수준 ≥ 학습 목표 수준
// (REMEMBER 목표를 가르쳤는데 ANALYZE 수준 평가는 불공정)
```

## 3. UDL — 보편적 학습 설계

Universal Design for Learning. WCAG가 "접근 가능하게"라면 UDL은 "모두가 더 잘 배우게".

### 세 가지 원칙

**1. 다양한 표현 수단 (Multiple Means of Representation)**
> "정보를 다양한 방식으로 제시하라"

- 텍스트 + 시각 자료 + 오디오 동시 제공
- 어려운 용어에 툴팁 또는 용어 사전 연결
- 복잡한 개념은 단계별로 분해
- 배경 지식 활성화 장치 (이전 학습 내용 연결)

**2. 다양한 행동·표현 수단 (Multiple Means of Action & Expression)**
> "학생이 이해를 다양한 방식으로 표현하게 하라"

- 객관식만 아닌 서술형, 그림 선택, 순서 배열 등
- 타이핑 대신 음성 입력 허용 (가능하다면)
- 중간 저장 및 수정 허용

**3. 다양한 참여 수단 (Multiple Means of Engagement)**
> "학습 동기를 다양한 방식으로 자극하라"

- 일상과 연결된 실생활 예시
- 선택권 제공 (문제 순서, 주제 선택)
- 적절한 도전 수준 (너무 쉽거나 너무 어렵지 않게)
- 진행 상황에 따른 즉각적 긍정 피드백

## 4. 학습 안전 환경 (Psychological Safety in Learning)

학습은 실수를 통해 이루어집니다. UI/UX가 실수를 두렵게 만들면 학습이 멈춥니다.

### 무엇이 학습 심리 안전을 해치는가?

| 해로운 패턴 | 이유 | 대안 |
|------------|------|------|
| "틀렸습니다. 0점" | 실패를 숫자로 낙인 | "다시 해봐요! 힌트: ..." |
| 빨간 X 아이콘만 표시 | 부정적 감정 강화 | 설명과 격려 함께 |
| 재시도 횟수 카운터 표시 | 압박감 조성 | 횟수 숨기기 (형성평가) |
| "실패" 애니메이션 | 창피함 유발 | 중립적 또는 격려 애니메이션 |
| 반 평균과 비교 표시 | 경쟁 유발, 자존감 저하 | 본인의 이전 기록과만 비교 |
| 시간 경과 경고음 | 시험 불안 유발 | 시각적으로만 표시, 소리 없이 |

### 성장 마인드셋 (Growth Mindset) 을 지원하는 언어

```
❌ 고정 마인드셋 표현 (피할 것)
- "틀렸습니다"
- "실패"
- "능력 부족"
- "못 했어요"

✅ 성장 마인드셋 표현 (사용할 것)
- "아직 아니에요 (Not yet)"
- "다시 도전해봐요"
- "조금 더 생각해봐요"
- "실수에서 배우는 중이에요"
```

## 5. 교육 데이터 특수 규정 (한국)

### 개인정보보호법 + 아동·청소년 특별 규정

| 연령 | 규정 | 코드 영향 |
|------|------|-----------|
| 만 14세 미만 | 법정대리인 동의 필수 | 회원가입 시 생년월일 수집 + 보호자 동의 플로우 |
| 전체 학생 | 최소 수집 원칙 | 불필요한 개인정보 수집 금지 |
| 전체 학생 | 목적 외 이용 금지 | 학습 목적 외 데이터 활용 금지 |

### 학교 정보시스템과의 차이

일반 SaaS와 달리 교육 데이터는:
- 졸업 후 데이터 처리 정책 필요 (장기 보존 vs 파기)
- 전학/전출 시 데이터 이관 정책 필요
- 학교 기관이 데이터 소유자 (학생 개인이 아닌 경우도 있음)

## 6. 알림 윤리 (Notification Ethics)

교육 앱은 학생의 학습 리듬을 존중해야 합니다.

```typescript
// ❌ 금지: 학습 시간 외 알림
function sendHomeworkReminder(studentId: string) {
  // 시간 확인 없이 즉시 발송
  sendPushNotification(studentId, "숙제 제출 마감!")
}

// ✅ 올바름: 적절한 시간에만 발송
function sendHomeworkReminder(studentId: string) {
  const now = new Date()
  const hour = now.getHours()

  // 저녁 9시 ~ 오전 8시 사이에는 알림 발송 금지
  if (hour >= 21 || hour < 8) {
    scheduleForNextMorning(studentId, "숙제 제출 마감!")
    return
  }

  sendPushNotification(studentId, "숙제 제출 마감!")
}
```

**알림 설계 원칙**:
- 학습 시간(오전 8시~오후 9시)에만 발송
- 알림 빈도 제한 (같은 날 3회 이상 금지)
- 학생·학부모가 수신 설정 직접 변경 가능해야 함
- 알림은 학습에 도움이 될 때만 (마케팅 목적 알림 금지)
