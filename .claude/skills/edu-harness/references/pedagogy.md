## 양쪽 동시 읽기 (revfactory 원칙)

코드 검토 전 반드시 파일 쌍을 동시에 열어 교차 확인:

```
□ API route (src/api/quiz/[id]/route.ts)
  + 프론트 훅 (src/hooks/useQuiz.ts)
  → 응답 shape이 일치하는가? isCorrect 포함됐는가?

□ DB 스키마 (prisma/schema.prisma 또는 src/types/quiz.ts)
  + API 비즈니스 로직
  → quiz.type 필드가 실제로 사용되는가?
  → maxAttempts 기본값이 FORMATIVE/SUMMATIVE별로 다른가?

□ 프론트 UI 컴포넌트 + 테스트 파일
  → 재시도 버튼이 DOM에만 있는가, 실제로 onClick 핸들러가 연결됐는가?
  → aria-live 영역이 실제로 피드백 텍스트를 업데이트하는가?
```

## 검토 체크리스트 5개 차원

**1. 평가 유형 코드 반영**
- [ ] quiz.type이 코드에서 실제로 분기 로직에 사용됨
- [ ] FORMATIVE일 때 재시도 로직이 활성화됨
- [ ] SUMMATIVE일 때 API 응답에 정답 정보 없음

**2. 오답·오류 메시지 심리 안전**
- [ ] 부정적 표현 없음
- [ ] 오답 피드백에 힌트 또는 격려 포함
- [ ] 재시도 버튼이 형성평가에서 항상 노출됨

**3. 프론트엔드 정답 노출 가능성**
- [ ] API 응답 타입에 isCorrect 없음
- [ ] 프론트 코드에서 정답을 추론할 수 있는 로직 없음 (예: score > 0이면 정답)
- [ ] DevTools Network 탭에서 정답 미노출 (수동 확인 권장)

**4. 진도 표시 성장 중심**
- [ ] 완료 수 기준 (N개 완료!)
- [ ] 결핍 중심 표현 없음 (N개 남음 ❌)
- [ ] 재시도 횟수 노출 없음 (형성평가)

**5. 재시도 정책**
- [ ] 형성평가: 재시도 버튼 + onClick 핸들러 연결 확인
- [ ] 총괄평가: 재시도 불가 처리 확인
