# Sprint Contract (스프린트 계약) 상세 가이드

## 왜 필요한가?

Anthropic $9 vs $200 연구: 완료의 의미를 사전에 합의한 팀이 압도적으로 높은 품질을 달성했다.
"완료"가 모호하면 AI는 작동하지 않는 기능도 완료로 선언한다.

## 계약 작성 원칙

```
스프린트 계약: [기능명]
날짜: [YYYY-MM-DD]

완료 조건 (이것들이 모두 작동해야 "완료"):
- [ ] [교육 기능 조건 예: 형성평가 재시도 버튼이 오답 시 즉시 표시됨]
- [ ] [기술 조건 예: isCorrect가 API 응답에 포함되지 않음]
- [ ] [접근성 조건 예: fieldset+legend로 문항 그룹화됨]
- [ ] [테스트 조건 예: 단위 테스트 3개 이상 통과]

비완료 조건 (이번 스프린트 범위 밖):
- [다음 스프린트로 미루는 항목]

Pedagogy Reviewer + verify.sh는 위 조건만으로 채점합니다.
```

## 좋은 조건 vs 나쁜 조건

| 나쁜 조건 ❌ | 좋은 조건 ✅ |
|-------------|------------|
| "퀴즈가 잘 동작함" | "오답 시 재시도 버튼이 즉시 표시됨" |
| "교육적으로 올바름" | "quiz.type: FORMATIVE 필드가 DB에 존재함" |
| "접근성 OK" | "fieldset+legend 구조 확인, aria-live 피드백 영역 존재" |
| "보안 문제 없음" | "isCorrect가 API 응답 JSON에 없음 (grep 결과 0건)" |
